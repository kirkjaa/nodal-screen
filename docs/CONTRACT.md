# NODAL Screen data contract (v1, 13 Nov 2026)

Owner: Claude Code. Cursor agents read it and build against it; they propose changes in their done note and never edit this file.

Everything the app shows comes from three kinds of file:

- `data/samples/<pid>.json`: one **session** per featured participant visit (format below).
- `data/cohort.json`: the **cohort** of synthetic participants for the programme view.
- `data/norms.csv` and `data/sources.json`: **reference values** and the sources they come from.

The front end never computes a flag. Flags, statuses and pathways are computed in Python (`screen/flags.py`) and written into the session file, so there is one place to review the rules.

## 1. Provenance

Every session and the cohort carry `provenance`, shown as a badge on every screen that displays them.

| Value | Badge text | Meaning |
|---|---|---|
| `synthetic` | Synthetic participant | Generated by `screen/gaitsynth.py`; no real person |
| `simulated-m1` | Simulated M1 capture | Synthetic movement rendered through the M1 emulator's camera models |
| `measured` | Measured, consenting adult volunteer | A real M1 capture with written consent (adults only) |

## 2. Session file

```json
{
  "schema": "nodal-screen/session@1",
  "provenance": "synthetic",
  "provenance_note": "Synthetic participant generated by screen/gaitsynth.py. No real person.",
  "participant": {
    "pid": "SYN-C-0007",
    "display_name": "Child 7",
    "group": "child",
    "age_y": 7, "age_band": "6-7", "sex": "F", "height_m": 1.22,
    "segment": {"site": "PHC-1", "nationality_group": "UAE national"},
    "consent": {"type": "guardian+assent", "date": "2026-11-14", "language": "ar"}
  },
  "visit": {"visit_id": "V2", "date": "2026-11-14", "site": "PHC-1", "kit": "M1, 4 cameras", "operator": "OP-02"},
  "qc": {"status": "ok", "confidence": "high", "strides_left": 6, "strides_right": 6,
         "keypoint_confidence": 0.91, "calib_residual_px": 0.4, "notes": []},
  "tasks": {
    "gait": {"metrics": ["<Metric>"], "curves": {"knee_flexion": {"left": [], "right": [], "norm_mean": [], "norm_sd": []}}},
    "tug":  {"metrics": ["<Metric>"]},
    "sts5": {"metrics": ["<Metric>"]},
    "sls":  {"metrics": ["<Metric>"]},
    "tandem": {"metrics": ["<Metric>"]},
    "hop":  {"metrics": ["<Metric>"]}
  },
  "flags": ["<Flag>"],
  "suggested_pathway": {"code": "WCV_DEV_REVIEW", "reason_flag_ids": ["F1"]},
  "review": null,
  "history": [{"visit_id": "V1", "date": "2025-11-10", "metrics": {"gait_speed": 1.12}}],
  "ai_texts": {}
}
```

- `group` is `child` (3 to 12) or `adult` (18+). A task that was not part of the visit is absent, not empty.
- `qc.status` is `ok` or `insufficient`. When it is `insufficient`, `flags` is empty, every metric's status is `insufficient`, `suggested_pathway.code` is `RECAPTURE`, and the screen says why from `qc.notes`.
- `curves` arrays have 101 points (0 to 100 % of the gait cycle), degrees. Curve names: `hip_flexion`, `knee_flexion`, `ankle_dorsiflexion`, `hip_adduction`.
- `review` is filled when a clinician acts: `{"clinician": "CLN-01", "decision": "confirm" | "dismiss" | "recapture", "pathway": "<code>", "note": "", "at": "<ISO time>"}`. In the hosted prototype, review actions are kept in the browser only and the screen says so.
- `ai_texts` holds texts written by a language model from the metrics and the clinician's decision, never from video: `{"family_letter": {"en": "", "ar": "", "model": "", "generated_at": "", "status": "stored-sample"}, "clinician_brief": {...}}`. The screen labels them "Drafted by AI from the measurements. A clinician approves before anything is sent."

### Metric

```json
{"id": "gait_speed", "side": null, "value": 0.86, "unit": "m/s",
 "ref": {"kind": "norm", "source_id": "bohannon2011", "mean": 1.30, "sd": 0.21, "z": -2.1},
 "status": "out_of_range"}
```

- `side` is `null`, `"left"` or `"right"`.
- `ref.kind` is `norm` (mean, sd, z), `cutoff` (`{"kind": "cutoff", "source_id": "steadi", "threshold": 12, "op": ">="}`) or `null` when no reference is loaded.
- `status`: `in_range`, `borderline`, `out_of_range`, `no_reference`, `insufficient`.

### Flag

```json
{"id": "F1", "rule": "cutoff", "severity": "flag", "title": "Timed Up and Go at or above the STEADI cut-off",
 "metric_ids": ["tug_time"], "evidence": "13.4 s, cut-off 12 s", "confidence": "high", "source_ids": ["steadi"]}
```

`severity` is `flag` (out of range) or `watch` (borderline). `confidence` comes from `qc.confidence`.

## 3. Metric catalogue

"Bad" is the direction that counts against the participant. Labels go through i18n with the id as key.

| id | Task | Unit | Side | Bad | Reference |
|---|---|---|---|---|---|
| `gait_speed` | gait | m/s | none | low | adult: norm `bohannon2011` and cut-offs `ewgsop2` / `awgs2019`; child: norm `lythgo2009` |
| `cadence` | gait | steps/min | none | both | norm |
| `stride_length` | gait | m | L/R | low | norm |
| `stride_length_h` | gait | stride / height | L/R | low | child norm when available |
| `step_time_cv` | gait | % | none | high | norm when available, else none |
| `double_support` | gait | % of cycle | none | high | norm |
| `step_length_si` | gait | % | none | high | NODAL rule (section 4) |
| `step_time_si` | gait | % | none | high | NODAL rule |
| `knee_rom` | gait | deg | L/R | low | none in v1 |
| `heel_first_share` | gait | % of strides | L/R | low | NODAL rule (toe-walking pattern) |
| `tug_time` | tug | s | none | high | cut-off `steadi`; norm `bohannon2006tug` |
| `sts5_time` | sts5 | s | none | high | cut-offs `ewgsop2` / `awgs2019`; norm `bohannon2006sts` |
| `sls_time` | sls | s | L/R | low | norm `springer2007` |
| `tandem_steps` | tandem | steps of 10 | none | low | none in v1 (shown, not flagged) |
| `hop_count` | hop | hops | L/R | low | none in v1 (shown, not flagged) |

## 4. Flag rules (`screen/flags.py`)

Applied only when `qc.status` is `ok`. Each rule writes its threshold and source into the flag so the screen can show it.

| Rule | Condition | Severity |
|---|---|---|
| `norm_z` | z beyond 2.0 in the bad direction | flag |
| `norm_z` | z between 1.5 and 2.0 in the bad direction | watch |
| `cutoff` | value meets the cut-off of the active cut-off set (config: `ewgsop2` default, `awgs2019` selectable; `steadi` always on for TUG) | flag |
| `asymmetry` | `step_length_si` or `step_time_si` at or above 15 % | flag |
| `asymmetry` | 10 % to 15 % | watch |
| `toe_walk` | child aged 3+, `heel_first_share` below 50 % on either side | flag |
| `toe_walk` | 50 % to 80 % | watch |
| `change` | `gait_speed` fell 0.10 m/s or more from the earliest visit in `history` (`perera2006`) | flag |
| `change` | fell 0.05 to 0.10 m/s | watch |

Symmetry index: `SI = 100 * |L - R| / (0.5 * (L + R))`.
The asymmetry and toe-walking thresholds are NODAL screening rules, not published cut-offs; their `source_ids` is `["nodal-rule"]` and the screen says "NODAL screening rule".

`qc.confidence`: `high` if at least 6 strides per side and keypoint confidence 0.85 or more; `medium` if at least 4 strides per side and 0.70 or more; otherwise `qc.status` becomes `insufficient`.

## 5. Suggested pathway

The first match wins. It is always a suggestion; the clinician chooses.

| Code | When | Label |
|---|---|---|
| `RECAPTURE` | `qc.status` insufficient | Repeat the capture |
| `WCV_DEV_REVIEW` | child with any flag, or two or more watches | Well-Child Visit developmental review |
| `FALLS_PREVENTION` | adult with a TUG, single-leg stance or gait-speed falls flag | Falls-prevention pathway |
| `ADULT_SARCOPENIA` | adult with a sit-to-stand or gait-speed cut-off flag | Adult comprehensive screening with sarcopenia assessment |
| `CLINICIAN_SPECIALIST` | adult with an asymmetry flag | Clinician review; specialist referral if the clinician agrees |
| `ADULT_EARLY_REVIEW` | adult with a change flag | Earlier adult screening review |
| `ROUTINE` | otherwise | Routine annual re-screen |

## 6. Cohort file

```json
{"schema": "nodal-screen/cohort@1", "provenance": "synthetic", "generated": "2026-11-14",
 "sites": [{"id": "PHC-1", "type": "Primary care centre"}, {"id": "SCH-1", "type": "School"}, {"id": "MAJ-1", "type": "Community majlis"}],
 "people": [{"pid": "SYN-A-0412", "group": "adult", "age_band": "65-74", "sex": "M", "nationality_group": "Non-national",
             "site": "MAJ-1", "invited": true, "screened": true, "flags": ["tug_time"], "pathway": "FALLS_PREVENTION",
             "flag_date": "2026-09-02", "attended_date": "2026-09-20"}]}
```

**Small-cell rule:** any count or rate whose cell has fewer than 10 people is shown as "<10" and is not plotted. Totals still show. (Complementary suppression is a pilot item; the About page says so.)

## 7. Reference files

`data/norms.csv` columns: `source_id, metric, sex (M/F/all), age_min, age_max, condition, mean, sd, n, table_ref, status`, with `status` one of `placeholder`, `transcribed` or `verified` (only Claude sets `verified`). A norm with `placeholder` status may drive the demo but the screen marks it "reference value pending verification".

`data/cutoffs.csv` columns: `source_id, metric, group, op, threshold, unit, meaning, table_ref, status`, same status values.

`data/sources.json`: `{"<source_id>": {"citation": "", "doi_or_url": "", "used_for": "", "verified": false}}`. Expected ids: `bohannon2011`, `lythgo2009`, `bohannon2006tug`, `bohannon2006sts`, `springer2007`, `steadi`, `ewgsop2`, `awgs2019`, `perera2006`, `nodal-rule`.
